Every number anybody has ever quoted about the American population came out of a building in Suitland, Maryland, and there are three ways to get it out. Two of them are open to anyone. The third is the only one a program can use, and it is the one that asks who you are.

Door What it is Needs a key Can you automate it
data.census.gov the website: search, click, download no not really
www2.census.gov the published files, exactly as released no yes, if you can parse the format
the API a URL that returns data yes yes — that is the point

All three return the same published counts. Which door you use decides what you can do, and the only one built for a program is the only one that is gated.

That arrangement has a consequence that is easy to state and unpleasant to sit with. A person clicking through fifty counties on a website is fine. A person cannot click through eight million census blocks, and blocks are the unit districts are drawn from. So the practical capacity to check a redistricting plan lives behind the door that asks for a name and an email address. The same goes for a lending pattern, or a language-assistance determination.

Registration for public data is defended as rate-limiting and abuse prevention, and objected to as an access barrier that falls hardest on people with no institutional affiliation. Both descriptions are accurate.

But the gate is not the most interesting thing about this API, and it is not what this chapter is mainly about. The half of it that requires nothing at all turns out to be the half worth reading.

A file that describes a file

The evidence in this chapter is not a measurement of anything. It is two catalogs. api_variables.csv has one row for each of the 338 columns the 2020 P.L. 94-171 release publishes. api_geography.csv has one row for each of the 96 geographic levels the same service will serve them at.

Both were fetched in August 2026 from the API’s open metadata endpoints, which need no key. The raw JSON responses are kept beside the CSVs, unmodified, so that anyone can see what actually came back rather than what somebody says came back. The whole of it is about 127 kilobytes.

Two different obligations are stacked inside those files and it is worth pulling them apart. Nothing requires the Census Bureau to run an API at all, or to publish a machine-readable description of one. That is a service the agency chose to build and could withdraw, and the key requirement is evidence that its terms can change.

But the columns listed in the catalog are not the Bureau’s choice. Public Law 94-171 obliges the Bureau to deliver redistricting tabulations to the states, and the tables that obligation produces are the tables the catalog lists. So the file is a voluntary description of a compulsory product. That is exactly why reading it closely tells you about the law, rather than about the Bureau’s preferences.

It is the right evidence for this chapter’s question and a poor fit for the question people usually think this chapter is asking. If the question is what does the United States measure about its own population, and how finely, a complete column list settles it outright. No sample, no estimate, nothing left out.

If the question is who is actually shut out by the key, the catalog cannot answer, and neither can anything else public. That would take the request logs, which nobody publishes, or a survey of the people who gave up, which nobody has run. What this chapter does instead is read the architecture and argue from it, and the difference between reading an architecture and measuring a harm is one a careful reader should keep in view. A second limit is temporal: a catalog describes the day it was fetched. The gate is recent, and the 2030 file will list different columns.

Cleaning was small and deliberately unglamorous. No JSON package is used. These two responses have a flat, predictable shape, so the fields come out with base R pattern matching. That is not a general parser, and is not pretending to be. The one real change is to the label field. The Bureau writes a variable’s position in its table as a string with !! between the levels, and that string has to be split before anything can be counted or drawn.

Nothing was dropped and nothing was renamed. No live query was made either when the CSVs were built or when this page is rendered, and there is no key anywhere here. A reader redoing it would need two curl commands and no account.

What came back, before anybody tidied it

Both raw responses are kept, so the two CSVs can be held against the thing they were made from. Here is the entry for one variable, lifted out of api_variables_2020pl.json exactly as it sits there.

And here is the entry for the smallest geography the service will serve, out of api_geography_2020pl.json.

Field as it arrives Value
name block

This is the gentlest arrival in the book. The response is already one object per thing, the fields already have names, and nothing has to be repaired. 338 variable objects came back and 338 rows were written; 96 geography objects came back and 96 rows were written. Not one row was dropped, filled in or reconciled against anything.

What happened instead was subtraction. The raw object carries 7 fields about this variable and the build keeps 3:

Variable Label Concept
P1_003N !!Total:!!Population of one race:!!White alone RACE

The raw object for a block carries 6 and the build keeps 2:

Level Name
100 block

Three decisions are visible in that shrinkage, and the second and third are losses worth knowing about.

Read the JSON with pattern matching, and admit that it only works here. The build uses no JSON package, because the labs are base R and base R has none. It finds each object with a pattern that assumes no object contains another object, which is true of these two responses and is not true of JSON in general. An endpoint that nested one level deeper would return something this code would read as gibberish rather than refuse.

The label is a tree flattened into a string, and it stays flattened. What the CSV keeps is the field as sent: !!Total:!!Population of one race:!!White alone. The !! are not decoration. They are the levels of the table hierarchy, and the leading space is real too. Anything a reader wants to know about where a column sits has to be recovered from that string by splitting it, which is what the next section does and what the figure after it draws.

The geography entry lost the part that says how to ask for it. The raw object says a block query requires state, county and tract, and that a wildcard is allowed for two of the three. The CSV keeps the level code and the name and drops the rest. For the argument in this chapter, which is about how far down the hierarchy goes, that is fine. For anybody trying to actually request eight million blocks it is the only field that mattered, and it is the first thing they would have to go back to the raw response for.

That is the whole of the cleaning. A catalog that describes itself is the one kind of file that arrives close to usable, and it is worth seeing once so that the other chapters’ files can be recognized for what they are.

The name of the thing is not the thing

The catalog is a file with one row per published column of the 2020 census.

Variable What it counts Which table it belongs to
P1_003N > Total: > Population of one race: > White alone RACE

The !! are nesting. P1_003N is Total > Population of one race > White alone — the number you would casually call “the white population.” It sits three levels down a hierarchy and it excludes everyone who ticked two boxes.

The name of the thing is not the thing, and no column announces the difference. A researcher who writes down P1_003N as “white population” has made a substantive claim about multiracial Americans without noticing.

Table P1 in full, drawn as the tree the !! describe, is a way of seeing where that column actually sits. Width is how many bottom-level categories lie underneath.

Figure 1. Table P1 as a tree, 4 levels deep and 63 bottom-level categories wide. Each block is one published column; a block’s width is the number of bottom-level categories beneath it, so the whole row at any depth accounts for the same population. The red block is P1_003N, “White alone,” 3 levels down. Its width is the point: it is one of several single-race categories, sitting under a branch that excludes everyone who ticked two boxes, and the orange branch beside it is where those people went.

The open half answers instantly, to anybody

File Rows What it lists Needs a key
api_variables.csv 338 every published column of the 2020 PL 94-171 file no
api_geography.csv 96 every geographic level you may ask for no

Neither file needs a key. Ask the API what exists and it answers instantly, to anybody; ask it for an actual number and it asks who you are. The consequence is that the information about how American democracy is measured is entirely public, while the measurements themselves are not.

Before you read on, commit to a number. The 2020 census form asked about ten things, and six tables carry the 301 substantive variables that came out of it. How many of those 301 are a table published a second time, rather than a distinct fact about anybody? Write down a count, or a share of 301. Then write down a second guess: of the 96 rows in the geography file, how many name a genuinely different level of geography?

A statute is visible in the shape of the file

Quantity Value
Substantive variables 301
of which restricted to the population 18 years and over 144
Share of the substantive file that is an adults-only twin 48%

“Duplicate” is a strong word, so check it directly. Count how many label strings each pair of tables has in common:

Figure 3. Two tables in six are the same table. Each cell counts the label strings two tables have in common. Off the diagonal, almost every pair shares exactly one: the row called “Total,” which every table has. The two red cells are the exceptions: P1 and P3 share 71 labels, and P2 and P4 share 73 — every row of both tables. They are not similar tables. They are identical, down to the wording.

Most readers put the duplication somewhere around a tenth, on the reasonable assumption that a statistical agency does not publish the same table twice. 144 of the 301 substantive variables are duplicates, or 48%. P3 is P1 restricted to adults. P4 is P2 restricted to adults. Nobody was asked a second time; the Bureau ran the same cross-tabulation twice and published both, and the only thing distinguishing the copies is which population it ran them on.

That is not curiosity, and it is not redundancy. The Voting Rights Act is about voters, and voters are adults. A §2 vote-dilution claim turns on whether a minority group is large enough to form a majority in a district, and the relevant population is voting-age. Without P3 and P4 the central quantity in American voting-rights litigation could not be computed from the census at all.

So the obvious reading of a big catalog is wrong here. That reading is that a statistical agency published a lot because there is a lot to know. Nearly half the substantive file exists because of a law, and you can read the law off the column list.

The same move works on the geography file.

Quantity Value
Rows in the geography file 96
Rows that are ‘(or part)’ fragments of a level already listed 67

of which sit below the county 7

96 levels are 29 levels. 67 of the rows are bookkeeping — the same level again, sliced by whatever larger unit it happens to straddle, because most American geographies do not nest. The catalog’s size is partly a law and partly the fact that the country is covered by two incompatible systems of boundaries.

Set the whole variables file out in three groups and there is very little of it left that is a fact somebody chose to collect.

7 of the 29 levels sit below the county, and one of them is voting district — a precinct.

The 67 “(or part)” rows are not spread evenly. They pile up on the levels that refuse to nest:

Figure 5. Where the geography file’s bulk actually comes from. Each dot is one geographic level, positioned by how many times it reappears in the catalog as an “(or part)” row. That is the same level again, sliced by whatever larger unit happens to cut across it. 20 levels generate all 67 fragment rows, and “county” alone accounts for 7 of them, because counties are cut by almost every other boundary the census publishes. Purple dots are levels that never appear in their own right at all: they exist only as fragments of something else.

The Census Bureau publishes population inside precinct lines. That is the join a voting-rights analysis needs, and it is exactly why the PL 94-171 file exists. A 1975 statute requires the Bureau to hand states the data they need to draw districts, on a deadline. The government publishes the data required to challenge the maps that government draws. That is deliberate, not circular.

The states helped build the file they are judged by

That last claim needs one qualification, and it is the most surprising thing in this chapter.

The Bureau does not know where a precinct is unless a state tells it. Precinct boundaries are set by counties and states and are not federal geography. So the Bureau runs a Redistricting Data Program across the whole decade, in five phases, and two of them are the states supplying it with information.

In the first phase, from 2015 to 2017, states were invited to say which roads, rivers and rail lines the Bureau should use as census block boundaries. In the second, from 2017 to 2020, states were invited to submit their own voting districts for inclusion in the P.L. 94-171 file. Only after that does the Bureau tabulate anything.

The second phase is voluntary, and that is what qualifies the claim above. A state that took part receives population summaries for its voting districts. A state that did not, does not. So the voting district row in the geography catalog is a capability of the service rather than a promise about any particular state, and this chapter’s catalog cannot tell you which states filled it in. That would take the Bureau’s own participation records.

The programme does not stop at delivery either. In a fourth phase the states send back the districts they actually drew, and the Bureau re-tabulates the 2020 counts inside them. In a fifth, running to 2025, the states write up what went wrong, for the 2030 round.

So the chapter’s opening description was one layer short. The catalog is a voluntary description of a compulsory product, and parts of that compulsory product were themselves supplied voluntarily, by the same states whose maps the file is used to challenge.

A locked door that answers politely

Ask the API what exists:

https://api.census.gov/data/2020/dec/pl/variables.json
https://api.census.gov/data/2020/dec/pl/geography.json

Both answer immediately, to anyone. Ask it for a number:

https://api.census.gov/data/2020/dec/pl?get=NAME,P1_001N&for=state:42

and since 2026 the answer is a page reading Missing Key.

The URL is the query, and the two doors return two different kinds of object:

Left: real bytes from data/api_variables_2020pl.json, one of 338 entries the open half will hand anybody. Right: what the same host returns when the key is missing — valid HTML that a program will happily parse into nothing.

Figure 6. One request, dissected, and the two kinds of object it can return. The URL is the query: a host, a dataset, a list of columns, and a filter naming where you want them. Ask the catalog for its own contents and the answer is the JSON on the left — real bytes from api_variables_2020pl.json, one of 338 entries the open half hands anybody who asks. Ask the same host for a population count without a key and the answer is on the right: not an error code, not malformed JSON, but a valid web page reading Missing Key.

Read the grammar segment by segment, because the URL is the query:

Piece Means
api.census.gov/data the host
2020/dec/pl the 2020 decennial census, Public Law 94-171 file
get=NAME,P1_001N the place name, and total population
for=state:42 state FIPS 42, which is Pennsylvania
for=county:*&in=state:42 every county in Pennsylvania instead

Now the failure. A missing key does not produce an error code or malformed JSON. It produces valid HTML. A script asking for numbers receives a web page and continues. Further down the line that becomes either an obvious explosion or, worse, a reader that quietly yields nothing and a table of zeroes nobody questions.

A locked door that returns a web page is worse than one that returns an error, because the failure is silent and surfaces later, in an analysis nobody re-reads. Returning a documented status code instead would cost the Bureau nothing, which is what makes it a design choice rather than an accident.

A key is a password

A key is free and arrives in about a minute from https://api.census.gov/data/key_signup.html. You then append &key=YOUR_KEY_HERE to any URL above.

A key is a password. It identifies you and it is not revocable by accident. Never put one in a file you share, a repository, a slide, or a handout.

This is not hypothetical. A live Census API key sat in plain text in a handout distributed to this course’s F25 section for a year. It has been flagged for revocation. The lesson is cheaper to learn from somebody else’s mistake.

Nothing in this chapter required one. Both files above came from the open endpoints, and no live query was ever run.

Whether a catalog is evidence, or only a menu

Should public data require registration? The Bureau’s position is operational: keys allow rate-limiting and abuse prevention, and the metadata stays open precisely so that discovery is unimpeded. The objection is that the gate falls on the automatable door while the point-and-click door stays open. That turns the usual direction of an access barrier upside down: it burdens systematic work and leaves casual lookup untouched. Both descriptions are accurate, and the disagreement is about which effect matters.

Is the catalog evidence, or just a menu? The reading above is that a file’s column list is a record of legal obligation. That is standard in the sociology of quantification, and contested in its strong form. The weak claim is safe: P3 and P4 exist because §2 litigation needs voting-age population, and the Bureau says so. The strong claim, that what a state measures reveals what it intends to govern, is an interpretation the data supports and does not prove.

And the deeper limit is that 18-and-over is not the quantity the law wants either. Voting-age population includes non-citizens and people barred from voting by felony conviction. For many §2 claims the right denominator, the bottom number you divide by, is citizen voting-age population. The decennial census does not publish that. It has to come from the American Community Survey, with margins of error attached. The Bureau publishes the closest thing it can measure, not the thing the law asks for, and courts have argued about that gap for decades.

What a column list can testify to

The evidence in this chapter is authoritative in a narrow sense and thin in a wide one, and it is worth being exact about which is which.

It is authoritative because both files came from the Bureau’s own endpoint, unmodified, and are complete for the dataset they describe. Nothing here is a sample, an estimate, or a reconstruction. It is also the only part of the API that can be checked without credentials, which is precisely why it is the part worth reading closely: the argument does not depend on anybody’s access.

It is thin because a catalog is not data. Nothing above establishes a single population count. The 2020 decennial PL file is the smallest thing the Bureau publishes. The American Community Survey has tens of thousands of variables, every one carrying a margin of error: a statement of how far off it could be. The PL file does not need one.

So the shape found here is the shape of one small, legally required product, rather than of federal statistics generally. The key policy changed recently, so a description of the API’s behavior describes a moment rather than a settled fact.

And labels are not definitions. The label field says where a variable sits in a table, not who is inside it. That is the whole trouble with P1_003N, and it is announced nowhere in the file.

So the sentence this chapter will bear is that the Census API is two services wearing one name: an open catalog and a gated data service. The open half is where the information about how American democracy gets measured actually lives. Sharper: of 338 catalog rows, 37 are identifiers, and 144 of the remaining 301 are the same tables recomputed for adults because the Voting Rights Act needs voting-age population. Of 96 geography rows, 67 are fragments of levels already listed. The catalog’s apparent generosity is mostly a statute and mostly bookkeeping.

What cannot be said is anything about what the gated half returns, since no live query was run. Nor that the published numbers are the numbers enumerators recorded. Publication involves withholding, rounding, and, since 2020, noise added on purpose. The number in the JSON is a processed number.

Three questions stay open. Whether the gate should exist at all for a dataset produced at public expense under constitutional mandate. Whether silent failure is defensible, given that returning a documented error code to a machine request would cost nothing. And whether the 2030 catalog will be comparable to this one. The 2024 revision of the federal race and ethnicity standards merges race and Hispanic origin into a single question. That will change the shape of P1 through P4, and with it every trend anybody has computed across decades.

The last of those is the one to sit with. This chapter read a 1975 statute off a column list 338 rows long. A reader in 2031 will open the same endpoint, find a different list, and be able to read a different law off it. That is either a remarkable property of public data or an uncomfortable one, depending on whether you think a government should be that readable.

Your turn

None of these is answered above, and every one can be answered from the tables you just opened.

  • api_variables.csv holds every variable the interface will answer for, with a label and a concept. Group by concept. What is this catalog mostly about, and what is barely in it at all?
  • Read down the label column in api_variables.csv and find a variable whose name does not tell you what it holds. How would you have found that out without the label?
  • api_geography.csv lists the levels you may ask for, each with a numeric level code. Sort by the code. Which geographies sit at the top of the hierarchy, and which ones are missing that you expected to see?
  • Pick one question you would genuinely want answered about your own county. Find the variable and the geography level that would answer it, or establish that neither exists.
